# 应用评论数据与证据口径

## 数据源选择

| 数据源 | 最佳用途 | 注意事项 |
|---|---|---|
| Play Console 月度 CSV | 历史回溯、零权限分析 | 常见 UTF-16 编码；通常没有真实国家字段；月末前下载可能为残缺月 |
| Android Publisher Reviews API | 每日增量、开发者回复 | 主要覆盖近 7 天的提交或修改；必须每日同步；需要 Play Console 应用权限 |
| GCS 批量报告 | 自动化历史回补 | 按月发布；需要 Storage Object Viewer 与 Play Console 授权 |

## 字段优先级

- 主键：Review Link 中的评论 ID；缺失时使用包名、提交时间、星级、正文、设备和语言组成的稳定 SHA-1 指纹。
- 版本：`App Version Code` 与 `App Version Name` 分列保存。
- 时间：使用提交时间统计趋势；使用最后修改时间处理用户修改后的评论。
- 设备：设备代号用于回归设备池，不能在没有映射表时直接标称厂商型号。
- 市场：`Reviewer Language` 只是语言，不是国家。

## 风险解释

- 差评率：默认 1-2 星 / 总评论数。
- 主题差评占比：命中主题的 1-2 星评论 / 命中主题评论数。它表示该主题的负向强度，不表示该主题导致的全部差评。
- 版本风险：必须同时显示样本数；低样本高差评率只用于排查线索。
- 趋势：若当月未覆盖整月，不能把提及数与完整月直接比较。可比较评分和差评率，或者按日归一化后再判断。

## 推荐证据表字段

| 字段 | 说明 |
|---|---|
| 问题 ID | 例如 PLAY-01 |
| 原文样本 | 保留原语言和必要上下文 |
| 星级/时间 | 体现严重度与新鲜度 |
| 版本/设备/市场代理 | 用于复现分组，不做过度推断 |
| 问题模式 | 用户可感知的具体失败路径 |
| 根因状态 | 已复现、日志支持、待验证、仅线索 |
| 需求决策 | P0/P1/P2/验证池 |
| 验收与回滚 | 可量化指标和止损动作 |
